# پایگاه دانش فروشگاه

این پوشه چیزی است که دستیار **از حفظ نمی‌داند** و باید در گفتگو پیدا کند: قیمت، موجودی، مشخصات، سیاست‌های فروشگاه و پیشنهادهای فعال.

## ساختار

```
knowledge/
  products/            یک فایل برای هر محصول
  store-policies.md    ارسال، پرداخت، مرجوعی، گارانتی، پشتیبانی
  marketing/           تخفیف‌های فعال و راهنمای انتخاب محصول برای هر نوع مشتری
```

فایل‌های نمونه (دو قهوه‌ساز و دو آسیاب) اینجا هستند تا از روز اول کار کند. **بعد از اینکه داده‌های واقعی خودتان را گذاشتید، این چهار فایل را پاک کنید** و ایندکس را دوباره بسازید:

```powershell
python scripts/build_rag_index.py
python scripts/check_retrieval.py
```

## مهم: رفتار دستیار در این پوشه نیست

نحوه‌ی فروش دستیار (لحن، مسیر گفتگو، اعتراض‌ها) در `prompts/sales_playbook.md` است، نه اینجا. آن فایل در هر پرامپت کپی می‌شود؛ این پوشه فقط با ابزار جست‌وجو خوانده می‌شود. **این دو را قاطی نکنید** — اگر راهنمای فروش را اینجا بگذارید، ممکن است به‌جای اطلاعات محصول بازیابی شود و دستیار به‌جای قیمت، نصیحت فروش بگوید.

## الگوی یک فایل محصول

```markdown
# نام کامل محصول (مدل)

## مشخصات
- ...

## قیمت و موجودی
- قیمت: ...
- موجودی: ... عدد
- رنگ‌های موجود: ...

## گارانتی و ارسال
- ...

## مناسب چه کسی است
یک پاراگراف کوتاه. این بخش همان چیزی است که به دستیار می‌گوید محصول را به چه کسی پیشنهاد بدهد.

## محدودیت‌ها (این را هم بگو)
عیب‌ها و محدودیت‌های واقعی. این بخش عمداً اجباری است؛ فروشنده‌ای که فقط تعریف می‌کند، مرجوعی می‌سازد.

## مقایسه با مدل دیگر
تفاوت با نزدیک‌ترین مدل، در یک جمله.
```

## نکته‌هایی که کیفیت بازیابی را تعیین می‌کنند

- **عنوان `#` نام محصول است و به هر تکه‌ی همان فایل می‌چسبد.** بدون آن، تکه‌ی «قیمت: ۳٫۸۵۰٫۰۰۰ تومان» هیچ نامی از محصول ندارد و سؤال «قیمت A1 چنده؟» پیدایش نمی‌کند.
- **هر ادعای عددی را با کلیدواژه‌ی خودش بنویسید.** «۳٫۸۵۰٫۰۰۰ تومان» را همان‌جا بنویسید که مشتری می‌پرسد، نه در جمله‌ای که شبیه معماست.
- **فارسی محاوره را جدی بگیرید.** موتور جست‌وجو «قیمتش»، «قهوه‌سازتون» و «ارزان‌ترین» را به شکل پایه برمی‌گرداند، ولی بهتر است خودتان هم شکل طبیعی جمله را در متن داشته باشید.
- **همیشه بگویید چه چیزی تخفیف ندارد.** اگر مشتری بپرسد و دستیار چیزی پیدا نکند، ممکن است تخفیف الکی بسازد.
- هرچه فایل‌ها کوچک‌تر و موضوعی‌تر باشند، بازیابی دقیق‌تر است. یک فایل صد محصولی، تکه‌های بی‌ربط می‌دهد.
- قیمت و موجودی را **تاریخ‌دار** نگه دارید در ذهنتان: این ایندکس ایستاست. بعد از هر تغییر قیمت، ایندکس را دوباره بسازید.

## به‌روزرسانی

این سیستم ایندکس ایستا دارد: قیمت و موجودی فقط با بازسازی ایندکس عوض می‌شوند.

```powershell
python scripts/build_rag_index.py     # بازسازی
python scripts/check_retrieval.py     # آیا هنوز پیدایش می‌شود؟
```

اگر می‌خواهید قیمت و موجودی همیشه زنده باشند، باید ایندکس از API فروشگاه (ووکامرس/شاپیفای) خوانده شود — بگویید تا اضافه کنم.
