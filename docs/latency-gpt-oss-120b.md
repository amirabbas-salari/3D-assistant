# بررسی تأخیر مدل `@cf/openai/gpt-oss-120b` روی Cloudflare Workers AI

## خلاصه‌ی اجرایی

- **پیش‌فرض پروژه** `llama-3.3-70b-instruct-fp8-fast` است (TTFT ~150-300ms برای صوت مناسب).
- `gpt-oss-120b` یک **reasoning model** است: پیش از اولین توکن «فکر» می‌کند؛ هر توکن فکر، اولین کلمه‌ی شنیدنی را عقب می‌اندازد.
- اندازه‌گیری همین پایپ‌لاین (۵ سؤال کوتاه متنی، بدون میکروفون):
  ```
  نوبت 1: 1.56s (36 نویسه)
  نوبت 2: 5.40s (123 نویسه)
  نوبت 3: 2.64s (14 نویسه)
  نوبت 4: 0.99s (84 نویسه)
  نوبت 5: 2.80s (179 نویسه)
  ```
  پراکندگی 1.0-5.4s برای هم‌اندازه‌ها → **عمق فکر**، نه شبکه یا طول پاسخ.

- بنچمارک بیرونی (Artificial Analysis، ۵ روز گذشته):
  - TTFT: 1.94s (low reasoning) / 9.03s (high) @ 205 tok/s
  - infer.com (ارائه‌دهنده‌ی دیگر) تا 388ms TTFT @ 713 tok/s — یعنی تأخیر به ارائه‌دهنده و reasoning وابسته است.

## چرا روی Workers AI کندتر است؟

1. `reasoning_effort` فقط برای نام‌های OpenAI خودکار پر می‌شود؛ مدل‌های `@cf/...` باید صریح بفرستند.
2. Workers AI مقدار پیش‌فرض reasoning را افشا نمی‌کند؛ `low` سریع‌ترین است ولی باز هم thinking دارد.
3. برخی endpointها شکل تودرتو `{"reasoning":{"effort":"low"}}` می‌خواهند؛ فیلد ناشناس 400 می‌دهد، پس پیش‌فرض خاموش است (`CLOUDFLARE_LLM_REASONING_NESTED=false`).

## چه چیزی کمک می‌کند (ترتیب اثر)

| کار | اثر واقعی |
|---|---|
| `CLOUDFLARE_LLM_REASONING_EFFORT=low` (پیش‌فرض همین است) | TTFT را از ~600ms به ~150ms در تست محلی آورد؛ روی gpt-oss-120b واقعی 1-5s → ممکن است به 1-2s بیاید |
| `AGENT_FAST_START=true` (پیش‌فرض) + جمله‌ی اول 5-9 کلمه | **TTS در مرز جمله‌ی اول** شروع می‌شود، نه بعد کل پاسخ؛ شروع شنیداری را ~200-400ms جلو می‌اندازد حتی اگر TTFT ثابت بماند |
| `AGENT_SPEED_PROFILE=fast` (endpointing 0.2s) | 100ms صرفه‌جویی قبل از LLM |
| تغییر مدل به `llama-3.3-70b-fp8-fast` | TTFT را از ثانیه به میلی‌ثانیه می‌آورد — **بزرگ‌ترین اهرم** |

`CLOUDFLARE_LLM_MAX_TOKENS` روی TTFT بی‌اثر است؛ فقط سقف خروجی است.

## چطور خودتان اندازه بگیرید

```bash
python scripts/check_llm_speed.py
python scripts/check_llm_speed.py --runs 5 --prompt "سلام، حالت چطوره؟"
# چهار حالت: بدون تنظیم / low / low+fast_start / medium → میانگین و بدترین TTFT
```

اگر `low` تفاوت معناداری نساخت:
- `CLOUDFLARE_LLM_REASONING_NESTED=true` را امتحان کنید
- یا `CLOUDFLARE_LLM_MODEL` را به `llama-3.3-70b` تغییر دهید

## توصیه برای این پروژه (صوت)

- برای **فروش صوتی** (پاسخ‌های کوتاه): `llama-3.3-70b` بمانید.
- اگر **استدلال عمیق** لازم است (مثلاً مقایسه‌ی فنی دو محصول با جدول): gpt-oss-120b با `low` + `AGENT_FAST_START`؛ قبول کنید که 1-2s تأخیر اولیه دارد و آن را با جمله‌ی اول کوتاه بپوشانید.
- لاگ `latency.py` هر نوبت `llm_node_ttft` و `llm_node_ttfs` را جدا گزارش می‌کند؛ اگر `ttfs - ttft < 400ms` یعنی مشکل بستن جمله نیست، همان thinking است.
